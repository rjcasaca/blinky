# Windows acceptance checks

Run these on the intended Windows PC. These tests have not been executed in the Linux development environment. Keep the results with OS version, GPU/driver, audio devices, preset, codec, and hardware encoding setting.

1. **First launch:** extract the portable archive into a path containing spaces. Start using `Start-Blinky.cmd` on a PC without .NET installed. Confirm the native prerequisite installs when missing and Blinky opens without further setup.
2. **Audio requirement:** try starting with no microphone and then no output device. Both must prevent recording. Deny microphone privacy access; the app must report a failure. Restore access, refresh, speak/play sound, and confirm both meters respond.
3. **Actual mix:** use headphones. Record 60 seconds: speak alone, play system audio alone, then do both. Play the saved file and confirm both sources are present. Repeat with both volume sliders at different levels. Confirm a paused interval is absent from the saved video and audio stays synchronized afterward.
4. **Sources:** record each monitor, a window, and a portrait/ultrawide screen. Check readable text, cursor position, aspect ratio and output resolution. Move a window between displays with different DPI. Check closed/minimized-window behavior and that refresh excludes Blinky itself.
5. **Tray and shortcuts:** hide and reopen the window while idle and recording. Check the microphone indicator clears when idle and hidden. Start/stop and pause/resume from another app using both shortcuts and tray controls. Quit while recording: the file must finalize before exit. Launch a second instance: only one may record.
6. **Audio stream lifecycle and device loss:** refresh sources several times, change each audio selection, then start/stop three short recordings. Intentional reopening must not produce a “capture stopped” error. Hide/reopen while idle and repeat. Then unplug the mic while recording. Repeat with the selected output. Within a few seconds, Blinky must stop/save and show an alert. Check the partial recording still contains both sources before the disconnect. Reconnect, refresh and start another recording.
7. **Disk reserve:** use a small disposable test volume as the output. Leave less than 512 MiB free and confirm start is rejected. Start with more space, consume it with a disposable file, and confirm recording stops before filling the volume. Keep unrelated files off that volume.
8. **Encoder matrix:** repeat short recordings with H.264 and HEVC, hardware on/off where available. If unsupported, confirm the failure is visible and a subsequent H.264 attempt can start. Compare Compact/Balanced/Smooth file size, text readability, CPU and GPU load.
9. **Three-hour soak:** record a typical work session in Balanced. Make a visible clap and audible cue near the beginning and end. Measure audio/video offset at both points; target drift under 100 ms. Track working set and handles every 10 minutes; investigate sustained growth after warm-up. Check seeking and playback at the end. Keep actual file-size results rather than assuming a preset guarantee.
10. **Crash recovery:** make a disposable recording for at least two minutes, then terminate Blinky in Task Manager. Restart and confirm it identifies the saved partial path. Open that original file in VLC and record how much was recovered. Repeat after restarting Windows during a disposable recording. Do not test this with valuable recordings.
11. **Smaller-copy installation and result:** stop a recording and choose **Create smaller copy**. Verify first-use download and progress, then create another copy while offline to confirm the cache is reused. Confirm the original's SHA-256 hash is unchanged, the HEVC file is smaller, text remains readable, and both mic and system sound play correctly. Check the saved percentage/MB and **Open smaller copy** action. Select an earlier file containing spaces/Unicode and repeat. Pre-create a `.smaller.mp4` and confirm it is preserved and a numbered copy is used.
12. **Optimization controls and failures:** cancel during the first-use download, encoding and playback verification. The original must remain and temporary job files must be removed. Start a recording while optimizing; compression must stop before capture starts. Hide/reopen the app during optimization and quit from the tray. Confirm quit stops the child process. Reject unfinished/no-audio files, check low-disk behavior, and confirm a larger result is not retained. Disconnect the network during first-use download and retry after restoring it. A failure must be shown in the panel without preventing a new recording.

13. **Window:** check two-column layout on 1080p/high-DPI displays, no scrollbar/overlaps, header dragging, resize, minimize, maximize/restore and close. Maximize should respect the taskbar; close/minimize keep recording in the tray. Check control contrast.
14. **Audio only:** record mic speech, system sound and both together. Confirm AAC with no video stream. Test pause/resume, unplug, low disk, first-use tool-download cancellation and quit. Soak for hours and check mic/system drift and bounded memory with mono, stereo, multichannel and 44.1/48 kHz endpoints.
15. **Meeting prompts:** join Teams/Zoom while hidden; accept the tray prompt and check audio-only capture. Test browser inclusion, each end grace, leave/rejoin, mute, previews, device changes and DND. Only prompt-started recordings may auto-stop. Manual recordings must continue; disabling prompts releases ownership; failed scans cannot stop a recording. This is mic-activity detection, not guaranteed call state.
16. **Class MCP:** generate snippets, connect Claude Desktop/Codex independently, transcribe full MP4/M4A classes and verify timestamps/terminology. Ask for detailed notes AND a separate summary and confirm complete transcript coverage. Customize a template, restart/reuse a job, cancel, fail/retry downloads and connect both clients at once. Workspace locking must prevent concurrent transcription; original recordings and old notes must remain intact.

Known gaps: screen capture has no independent worker, no file rotation/remux repair and no AV1. Meeting detection uses microphone activity. The redesigned window and native live audio mixing/drift have not run on Windows in this environment. Protected content, multi-GPU and hot-plug behavior need particular attention.
